# config-import Specification

## Purpose

Экспорт и импорт конфигурации симулятора в JSON-файл, а также хранение той же конфигурации в браузере. Импорт проверяет файл целиком и либо заменяет конфигурацию, либо оставляет прежнюю без изменений.

## Requirements

### Requirement: Экспорт текущей конфигурации

Система SHALL отдавать по ссылке `export-link` файл `access-policy-config.json` с текущей конфигурацией: объект с целочисленным полем `version` и списками `users`, `groups`, `services`, `permissions`. Файл экспорта и сохранённая копия в браузере MUST иметь один и тот же формат.

#### Scenario: Экспорт после изменения

- **WHEN** разрешение `p5` удалено и человек открывает `export-link`
- **THEN** ссылка содержит конфигурацию без `p5` в формате файла импорта, а атрибут `download` равен `access-policy-config.json`

#### Scenario: Экспорт и импорт дают ту же конфигурацию

- **WHEN** экспортированный файл загружают обратно
- **THEN** конфигурация после импорта равна исходной

### Requirement: Импорт заменяет конфигурацию целиком

Корректный файл, загруженный через `import-input`, SHALL после нажатия `import-confirm` заменять конфигурацию целиком и сохранять её в браузере, за одним исключением: отзывы текущей конфигурации сохраняются по требованию «Отзыв переживает загрузку старого файла». До подтверждения показывается предпросмотр (`import-preview`), конфигурация не меняется. После подтверждения экран показывает `import-status` с текстом «Конфигурация заменена».

#### Scenario: Корректный файл

- **WHEN** загружен корректный файл с одним разрешением группы «Поддержка» и нажата `import-confirm`
- **THEN** список разрешений состоит из одной строки, `import-status` сообщает «Конфигурация заменена», а `localStorage` под ключом приложения хранит тот же файл

### Requirement: Файл проверяется целиком до изменения данных

Импорт MUST проверять весь файл до изменения конфигурации и собирать все ошибки, а не только первую. При хотя бы одной ошибке конфигурация и сохранённая копия в браузере MUST остаться прежними, а экран показывает `import-error` со списком ошибок. Проверяются: разбор JSON, корень-объект, целое поле `version` не новее поддерживаемой версии, наличие четырёх списков, форма каждой записи, уникальность идентификаторов внутри списка и ссылки разрешений и участия в группах на существующие записи.

#### Scenario: Ссылка на несуществующий сервис

- **WHEN** в файле у `permissions[0]` указан сервис `vault`, которого нет
- **THEN** `import-error` содержит «permissions[0]: нет сервиса «vault»», список разрешений прежний, а `localStorage` не изменился

#### Scenario: Несколько ошибок

- **WHEN** в файле две ошибки ссылок в разных разрешениях
- **THEN** список ошибок содержит обе

#### Scenario: Файл не JSON

- **WHEN** загружен текст `{oops`
- **THEN** `import-error` сообщает «Файл не разбирается как JSON»

#### Scenario: Версия новее поддерживаемой

- **WHEN** в файле `version` больше поддерживаемой
- **THEN** файл отвергается с сообщением о версии

### Requirement: Неизвестные поля игнорируются

Импорт SHALL игнорировать неизвестные поля в корне и в записях, чтобы файлы с будущими необязательными полями читались.

#### Scenario: Лишнее поле

- **WHEN** в файле есть поле `exportedBy` и у пользователя поле `nickname`
- **THEN** файл принимается, а конфигурация равна той, что без лишних полей

### Requirement: Ошибка импорта не мешает следующему файлу

После отвергнутого файла следующий корректный файл SHALL приниматься в предпросмотр, а `import-error` исчезает.

#### Scenario: Ошибка, затем корректный файл

- **WHEN** сначала загружен `{oops`, затем корректный файл
- **THEN** показан `import-preview`, а `import-error` скрыт; после `import-confirm` показан `import-status`

### Requirement: Сохранённая копия в браузере

Конфигурация SHALL сохраняться в `localStorage` под ключом `access-policy-simulator:config` после каждого изменения и читаться при открытии страницы. Если сохранённого нет, оно повреждено или нарушает ссылочную целостность, приложение MUST открываться на учебных данных.

#### Scenario: Изменения переживают перезагрузку

- **WHEN** удалено разрешение `p3` и страница открыта заново
- **THEN** в списке четыре разрешения и нет `p3`

#### Scenario: Повреждённая копия

- **WHEN** под ключом приложения лежит `{oops`
- **THEN** приложение открывается на учебных данных

### Requirement: Интервал разрешения в файле

Разрешение в файле конфигурации и в сохранённой копии SHALL нести необязательные поля `startsAt` и `expiresAt` со значением вида `2026-03-01T09:00`. Поле без значения MUST NOT записываться в файл. Импорт MUST отвергать файл, если значение поля не строка этого вида или не существующая дата, либо если оба поля заданы и окончание не позже начала. Версия формата остаётся `1`.

#### Scenario: Экспорт и импорт временного разрешения

- **WHEN** конфигурацию с временным разрешением экспортируют и загружают обратно
- **THEN** интервал разрешения сохранился без изменений

#### Scenario: Постоянное разрешение без новых полей

- **WHEN** экспортируется конфигурация, где все разрешения постоянные
- **THEN** в файле у разрешений нет полей `startsAt` и `expiresAt`

#### Scenario: Неверный формат времени

- **WHEN** в файле у `permissions[0]` поле `expiresAt` равно `16.03.2026`
- **THEN** файл отвергается с ошибкой «permissions[0]: поле expiresAt должно иметь вид ГГГГ-ММ-ДДTчч:мм», конфигурация не меняется

#### Scenario: Окончание раньше начала в файле

- **WHEN** в файле у разрешения `expiresAt` не позже `startsAt`
- **THEN** файл отвергается с ошибкой про окончание срока

### Requirement: Файлы прежнего формата

Файл конфигурации прежнего формата, без полей интервала, SHALL приниматься, после `import-confirm` `import-status` сообщает «Конфигурация заменена», а все его разрешения считаются постоянными на любой момент расчёта.

#### Scenario: Старый файл

- **WHEN** загружен файл, выгруженный до появления временного доступа, и нажата `import-confirm`
- **THEN** `import-status` сообщает «Конфигурация заменена», а ответы расчёта для любой пары и любого `evaluation-time` такие же, как до этого изменения

### Requirement: Момент отзыва в файле

Разрешение в файле конфигурации и в сохранённой копии SHALL нести необязательное поле `revokedAt` вида `2026-03-01T09:00`. Поле пишется только у отозванного разрешения: экспорт конфигурации без отзывов MUST NOT содержать `revokedAt`. Импорт MUST отвергать файл, если `revokedAt` неверного вида или стоит у постоянного разрешения (без начала и окончания).

#### Scenario: Отзыв переживает экспорт и импорт

- **WHEN** конфигурацию с отозванным `p6` экспортируют и загружают обратно
- **THEN** `p6` по-прежнему отозвано с того же момента

#### Scenario: Экспорт без отзывов

- **WHEN** в конфигурации нет отозванных разрешений
- **THEN** в файле экспорта нет поля `revokedAt`

#### Scenario: Отзыв у постоянного разрешения в файле

- **WHEN** в файле у постоянного `permissions[0]` есть `revokedAt`
- **THEN** файл отвергается с ошибкой «permissions[0]: отзыв возможен только у временного разрешения»

### Requirement: Файлы без поля отзыва

Файл конфигурации прежнего формата, без поля отзыва и без временных разрешений, SHALL приниматься, после `import-confirm` `import-status` сообщает «Конфигурация заменена», кнопок `permission-revoke-<id>` в списке нет, а доступ считается так же, как до досрочного отзыва.

#### Scenario: Старый файл

- **WHEN** загружен файл учебной конфигурации, выгруженный до этого изменения, и нажата `import-confirm`
- **THEN** `import-status` сообщает «Конфигурация заменена», в списке нет ни одной `permission-revoke-<id>`, а Анна Белова имеет доступ к «Учёту» по двум источникам на любой момент

### Requirement: Отзыв переживает загрузку старого файла

При подтверждении импорта система MUST сохранять отзыв текущей конфигурации у той же записи файла (тот же идентификатор, субъект, сервис, начало и окончание): если в файле отзыва нет или он позже, остаётся текущий, иначе — отзыв из файла. Всё остальное берётся из файла. До подтверждения запись названа строкой `import-preview-kept-<id>`, после — `import-status` SHALL добавлять «Сохранён отзыв: <id>, …». Ограничения — в требовании «Ограничения слияния импорта».

#### Scenario: Инцидент — экспорт, отзыв, загрузка того же файла

- **WHEN** Вере Лисицыной, у которой нет других источников доступа к «Почте», выдано временное разрешение `p6` на «Почту» `[2026-03-02T09:00, 2026-03-16T18:00)`, конфигурация экспортирована по `export-link`, `p6` отозвано с `2026-03-09T00:00`, затем через `import-input` загружен сохранённый файл и нажата `import-confirm`
- **THEN** на `evaluation-time` = `2026-03-12T12:00` `access-result` отвечает «Доступа нет», `access-sources` не показывается, а `import-status` сообщает «Конфигурация заменена» и «Сохранён отзыв: p6»

#### Scenario: Тот же файл без отзыва в текущей конфигурации

- **WHEN** временное разрешение выдано, конфигурация экспортирована, и тот же файл загружен без отзыва и подтверждён
- **THEN** на момент внутри интервала `access-result` отвечает «Доступ есть», а строки о сохранённых отзывах нет

#### Scenario: Запись с тем же идентификатором, но другим содержимым

- **WHEN** в текущей конфигурации отозвано `p6` Бориса Каримова на «Почту», а в файле `p6` — разрешение Веры на «Почту»
- **THEN** после импорта `p6` равно записи из файла, без отзыва

#### Scenario: Более ранний отзыв в файле

- **WHEN** в текущей конфигурации `p6` отозвано с `2026-03-09T00:00`, а в файле та же запись отозвана с `2026-03-05T00:00`
- **THEN** после импорта `p6` отозвано с `2026-03-05T00:00`

#### Scenario: Файл с ошибкой

- **WHEN** после отзыва загружен файл со ссылкой на несуществующий сервис
- **THEN** показан `import-error`, отзыв на месте, а `localStorage` не изменился

### Requirement: Ограничения слияния импорта

Запись файла с тем же идентификатором, но другим субъектом, сервисом или интервалом SHALL считаться другой записью и браться из файла без отзыва. Разрешение, удалённое после экспорта, возвращается из файла, а выданное после экспорта пропадает. Это осознанные ограничения: расхождения видны в списке разрешений, а с предпросмотром импорта — до подтверждения.

#### Scenario: Удалённое после экспорта возвращается

- **WHEN** после экспорта учебной конфигурации удалено `p5`, а затем загружен и подтверждён экспортированный файл
- **THEN** `p5` снова в списке разрешений
