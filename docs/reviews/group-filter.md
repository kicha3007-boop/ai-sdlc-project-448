## Соответствие артефактам (А)

- Задачи 1.1–1.3 и 2.1–2.3 реализованы: `src/app/users.ts`, `src/app/users.test.ts`, `listUsers` в `src/app/index.ts`, `group-filter` и `changeGroup` в `src/components/App.tsx`, `src/components/GroupFilter.test.tsx`. Задачи 3.1 и 3.2 по диффу не проверить. `npx vitest run` при ревью дал 8 файлов и 61 тест, все прошли. Задача 3.3 — находка 4.
- Поведения, которого нет в артефактах, в диффе нет. Сброс выбора в обработчике, а не эффектом, соответствует design, решение 3. Отбор сотрудника из нескольких групп соответствует design, раздел Risks.

## Ограничения СБ (Б)

1. Конфигурация остаётся в браузере — следствие истинно: в диффе нет `fetch`, `XMLHttpRequest`, `sendBeacon` и `WebSocket`. Новый код только фильтрует `config.users` в памяти.
2. Импорт проверяется целиком — следствие истинно: `config-file.ts`, `storage.ts` и `importJson` дифф не трогает.
3. Операции затрагивают только выбранные разрешения — следствие истинно: `permissions.ts`, `grantPermission` и `revokePermission` не изменены, а `usersInGroup` не мутирует конфигурацию (возвращает `config.users` или результат `filter`).
4. Отзыв сохраняет независимые источники — следствие истинно: `src/domain/access.ts` не изменён. Фильтр не участвует в `checkAccess`, а тест «участник группы остаётся выбранным» подтверждает оба источника доступа Анны к «Учёту».

## Архитектурные правила (В)

- Единый модуль расчёта — соблюдено: доступ считает только `calculateAccess` через `checkAccess`. Фильтр отбирает список и доступ не пересчитывает.
- Время передаётся параметром — соблюдено: `src/domain` не изменён, новых чтений часов в домене нет.
- Компоненты ходят к конфигурации через слой приложения — соблюдено: `App.tsx` получает `listUsers` из `useSimulator` и импортирует только из `../app`. Импортов `src/domain` и `localStorage` в коде компонентов нет.
- Граница типов — соблюдено: `User` объявлен в `src/domain/model` и уже реэкспортируется из `src/app/index.ts`. `src/app/users.ts` берёт типы из домена как слой приложения, новых общих типов изменение не вводит.

## Покрытие сценариев (Г)

- «Состояние по умолчанию» — `GroupFilter.test.tsx`, «по умолчанию выбраны все группы и видны все сотрудники».
- «Выбрана группа» — `GroupFilter.test.tsx`, «при выбранной группе показывает только её участников».
- «Возврат ко всем группам» — `GroupFilter.test.tsx`, «возврат к «Все группы» снова показывает всех» (слабая проверка, находка 2).
- «Группа без участников» — только `users.test.ts`, «для группы без участников отдаёт пустой список», без экранного теста (находка 1).
- «Сотрудник входит в группу» — `GroupFilter.test.tsx`, «участник группы остаётся выбранным, и ответ расчёта прежний».
- «Сотрудник не входит в группу» — `GroupFilter.test.tsx`, «сотрудник не из группы сбрасывается и не возвращается сам», первая часть (другой порядок шагов, находка 3).
- «Сброшенный выбор не возвращается» — тот же тест, вторая часть, после выбора «Все группы».

## Повторное ревью

Входы: дифф `b3e3166~1..8ef2398`, те же артефакты `openspec/changes/group-filter/`, `docs/security-requirements.md`, `docs/architecture.md`, `CLAUDE.md` проекта.

- Находка 1 — закрыта: в `src/components/GroupFilter.test.tsx` добавлен тест «для группы без участников оставляет только «Не выбран»». Он кладёт в `localStorage` конфигурацию с пустой группой «Северная» и сверяет `user-select` с `["Не выбран"]`. Импорт `seed`, `STORAGE_KEY` и `exportConfig` из `src/app` разрешён разделом «Тесты» в `docs/architecture.md`, а `beforeEach(() => localStorage.clear())` в `src/test-setup.ts` не даёт состоянию перейти в другие тесты.
- Находка 2 — закрыта: в тесте «возврат к «Все группы» снова показывает всех» `toHaveLength(4)` заменён на сверку полного списка `["Не выбран", "Анна Белова", "Борис Каримов", "Вера Лисицына"]`.
- Находка 3 — закрыта: из теста «сотрудник не из группы сбрасывается и не возвращается сам» убран первый шаг с «Бухгалтерией». Теперь шаги идут так же, как в сценарии: Анна и «Учёт» при «Все группы», затем «Поддержка».
- Находка 4 — закрыта, с отклонением согласен: отчёт `docs/reviews/group-filter.md` вошёл в дифф изменения, а задача 3.3 закрывается им до архивации. Оговорка: в снимке `8ef2398` столбец «Решение» в таблице пустой, решения есть только в текущем рабочем файле. Задача 3.3 закрыта, только если отчёт попадёт в ветку вместе с решениями.
- Находка 5 — не закрыта, с отклонением не согласен. Довод «правило в `CLAUDE.md` появилось позже» противоречит истории. Раздел «Процесс» с этим правилом есть в `CLAUDE.md` уже в коммите `bb1c45a`, родителе `b3e3166`, и дифф `CLAUDE.md` не меняет. Значит, правило действовало, когда изменение начиналось. В правиле нет исключения для состояния экрана: оно требует описать, что станет «с новым полем или состоянием» после экспорта, импорта старого файла и перезагрузки. Выбранная группа — это новое состояние (`design.md`, решение 2), и `design.md` сам называет случай с импортом в Risks. Закрыть находку можно коротким разделом в `design.md`: группа в файл и хранилище не попадает, после перезагрузки снова «Все группы», после импорта удалённая группа ведёт себя как пустая. Код менять не нужно.

Новых нарушений не найдено. Задачи 1.1–2.3 соответствуют диффу, четыре ограничения СБ и три архитектурных правила вместе с границей типов соблюдены. Новые правки трогают только тесты. Теперь каждый из семи сценариев спеки проверяет экранный тест в `src/components/GroupFilter.test.tsx`.

Итого повторного ревью: открыта medium — 1 (находка 5), закрыты low — 4 (находки 1–4); новых находок: high — 0, medium — 0, low — 0.


Решение автора по итогам повторного ревью: находка 5 принята и исправлена — раздел «Взаимодействие с импортом, экспортом и сохранённой копией» добавлен в `openspec/changes/group-filter/design.md` (см. колонку «Решение»).
