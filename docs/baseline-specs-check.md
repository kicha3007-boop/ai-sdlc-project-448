# Сверка базовых спек с кодом и тестами

Шаг настройки процесса: базовые спеки `openspec/specs/access-calculation/spec.md` и
`openspec/specs/config-import/spec.md` извлечены из кода стартера, каждый сценарий подтверждён
тестом или местом в коде. Таблица составлена до первого изменения и описывает стартер.

## access-calculation

| Сценарий | Тест или место в коде |
| --- | --- |
| Прямое разрешение даёт доступ | `src/components/App.test.tsx` «показывает доступ по прямому разрешению»; `src/domain/access.test.ts` «даёт доступ по прямому разрешению» |
| Разрешение группы даёт доступ участнику | `src/components/App.test.tsx` «показывает доступ по разрешению группы» |
| Чужая группа и другой сервис не дают доступа | `src/domain/access.test.ts` «не берёт разрешения чужих групп и других сервисов» |
| Прямой и групповой источники вместе | `src/components/App.test.tsx` «показывает прямой и групповой источники вместе»; `src/domain/access.test.ts` «называет прямой и групповой источники вместе» |
| Нет разрешений, нет доступа | `src/components/App.test.tsx` «сообщает об отсутствии доступа» |
| Ответ не зависит от времени вызова | `src/domain/access.test.ts` «принимает момент расчёта параметром…» |
| Ничего не выбрано | `src/components/App.test.tsx` «предлагает выбрать сотрудника и сервис до расчёта» |
| Удаление прямого разрешения при наличии группового | `src/components/Permissions.test.tsx` «отзыв одного разрешения сохраняет независимый источник доступа»; `src/app/permissions.test.ts` «сохраняет независимый источник…» |
| Удаление единственного источника | `src/app/permissions.test.ts` «закрывает доступ, когда источник был единственным», «убирает только выбранное разрешение» |
| Новая выдача учитывается расчётом сразу | `src/components/Permissions.test.tsx` «добавляет разрешение, и расчёт сразу его учитывает» |
| Повторная выдача | `src/components/Permissions.test.tsx` «сообщает о повторной выдаче и не создаёт дубль» |

## config-import

| Сценарий | Тест или место в коде |
| --- | --- |
| Экспорт после изменения | `src/components/Permissions.test.tsx` «отдаёт текущую конфигурацию для скачивания…» |
| Экспорт и импорт дают ту же конфигурацию | `src/app/config-file.test.ts` «возвращает ту же конфигурацию после экспорта и импорта» |
| Корректный файл | `src/components/Permissions.test.tsx` «заменяет конфигурацию целиком и сохраняет её в браузере» |
| Ссылка на несуществующий сервис | `src/components/Permissions.test.tsx` «отвергает некорректный файл…»; `src/app/config-file.test.ts` «…на несуществующий сервис» |
| Несколько ошибок | `src/app/config-file.test.ts` «собирает все ошибки файла, а не только первую» |
| Файл не JSON | `src/app/config-file.test.ts` «отвергает текст, который не разбирается как JSON» |
| Версия новее поддерживаемой | `src/app/config-file.test.ts` «отвергает версию новее поддерживаемой» |
| Лишнее поле | `src/app/config-file.test.ts` «игнорирует неизвестные поля…» |
| Ошибка, затем корректный файл | `src/components/Permissions.test.tsx` «после ошибки следующий корректный файл принимается…» |
| Изменения переживают перезагрузку | `src/components/Permissions.test.tsx` «изменения переживают перезагрузку страницы» |
| Повреждённая копия | `src/app/storage.test.ts` «возвращается к учебным данным, если сохранённое повреждено» |

Неподтверждённых сценариев не осталось. Сценарий «Сохранённая копия при нарушении ссылочной
целостности» подтверждён `src/app/storage.test.ts`, но в спеку вошёл текстом требования, а не
отдельным сценарием.
