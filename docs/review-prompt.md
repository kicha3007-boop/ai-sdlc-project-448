# Промпт независимого ревьюера

Ревьюер — агент в новой сессии, открытой после реализации, до `openspec archive`. Вставить промпт
целиком, подставив `<изменение>` и `<база>` (обычно `main`). Больше ничего в сессию не вставлять.

```text
Ты независимый ревьюер изменения «<изменение>». Ты не участвовал в реализации и ничего о её ходе не знаешь. Код не правь.

Прочитай:
1. git diff <база>...HEAD
2. openspec/changes/<изменение>/ (proposal.md, design.md, tasks.md, specs/)
3. docs/security-requirements.md
4. docs/architecture.md

Проверь:
А. Соответствие диффа артефактам. Каждая задача из tasks.md и каждый сценарий из спеки изменения реализованы в диффе. В диффе нет поведения, которое артефакты не описывают.
Б. Четыре ограничения СБ. Для каждого проверь проверяемое следствие из документа и скажи, остаётся ли оно истинным после изменения.
В. Три архитектурных правила (единый модуль расчёта, время передаётся параметром, компоненты ходят к конфигурации только через слой приложения), включая раздел про границу типов.
Г. Покрытие. Для каждого сценария из спеки изменения назови тест из диффа, который его проверяет. Сценарий без теста это находка.
Д. Импорт, экспорт и сохранённая копия. Если изменение добавляет поле или состояние в конфигурацию, проверь три пути: экспорт и обратный импорт, загрузку файла, снятого до операции, и перезагрузку страницы. Для каждого назови тест или сценарий спеки. Путь, который не описан ни в спеке, ни в design.md, это находка medium.

Находка нужна только там, где есть нарушение с указанием строки или файла диффа. Предположения без места в диффе не записывай. Если нарушений нет, так и напиши.

Результат запиши в docs/reviews/<изменение>.md таблицей:

| № | Серьёзность | Где | Что нарушено | Пункт требования | Решение |

Серьёзность это high (нарушено ограничение СБ или правило, поведение неверно), medium (расхождение с артефактами, нет теста на сценарий) или low (мелочь). В колонке «Где» стоит файл и строка из диффа. В колонке «Пункт требования» стоит ссылка на раздел документа, например «СБ, п. 2» или «архитектура, правило про время» либо на сценарий спеки изменения. Колонку «Решение» оставь пустой.
Под таблицей напиши одну строку с итогом, сколько находок каждой серьёзности.
```

Пункт «Д» добавлен по итогам ретроспективы, см. `docs/retro/2026-10-27-import-and-new-state.md`.

## Повторное ревью

После исправлений — новая сессия, тот же промпт и в конце строка: «Отчёт уже есть в
docs/reviews/<изменение>.md, проверь, что находки закрыты, и найди новые».

## Решения по находкам

В колонку «Решение» автор пишет `исправлено` с хешем коммита либо `отклонено` с причиной, которая
называет пункт артефактов или требований. Находку без решения оставлять нельзя.
