# Симулятор политик доступа

[![hexlet-check](https://github.com/kicha3007-boop/ai-sdlc-project-448/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/kicha3007-boop/ai-sdlc-project-448/actions)

Научитесь вести разработку с ИИ-агентом по спецификации: от требований до проверенного изменения.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-sdlc
Как это должно работать: https://github.com/hexlet-components/projects-ai-sdlc-access-policy-simulator

Симулятор для администратора доступов: выбираете сотрудника, сервис и момент времени — приложение
отвечает, есть ли доступ, и объясняет, за счёт каких разрешений. Разрешения выдаются постоянно или
на интервал, временные можно досрочно отозвать, конфигурация выгружается в JSON и загружается
обратно через предпросмотр. Данные учебные и хранятся только в браузере.

## Стек

- TypeScript, React 19, Mantine, Vite
- Vitest + Testing Library, oxlint + oxfmt, ast-grep
- OpenSpec (спецификации и изменения), скиллы агента в `.claude/skills/`

## Установка

Нужен Node.js 22.22+ или 24.15+ (в CI — 26, см. `.github/workflows/ci.yml`).

```bash
git clone https://github.com/kicha3007-boop/ai-sdlc-project-448.git
cd ai-sdlc-project-448
make install        # npm ci
```

Переменных окружения и ключей приложению не нужно.

## Использование

```bash
make dev            # dev-сервер Vite: http://localhost:8080
make build          # проверка типов и сборка в dist/
make start          # предпросмотр сборки: http://localhost:8080
make setup          # install + build (так собирает CI и Pages)
```

Сценарий на учебных данных:

1. Выберите «Анна Белова» и «Учёт» — доступ есть по двум источникам, ниже объяснение со статусами.
2. Выдайте Вере Лисицыной «Почту» с полями «Действует с» / «Действует до», меняйте «Момент
   расчёта» — доступ есть только внутри интервала (начало входит, окончание нет).
3. Отзовите временное разрешение кнопкой «Отозвать досрочно» с моментом в поле «Момент отзыва».
4. Экспортируйте конфигурацию, загрузите файл обратно — до кнопки «Применить» виден предпросмотр
   различий, отзывы, сделанные после экспорта, сохраняются.

## Проверки

```bash
make test           # vitest
make lint           # oxlint + проверка форматирования oxfmt
make lint-arch      # ast-grep по src с правилами из rules/
npx @fission-ai/openspec validate --all --strict   # или openspec validate --all --strict
```

## Процесс разработки

- `CLAUDE.md` — инструкция агента: раскладка, команды, правила процесса.
- `docs/architecture.md`, `docs/security-requirements.md` — архитектурные правила и ограничения СБ.
- `docs/adr/` — решения (представление времени).
- `openspec/specs/` — текущие спеки; `openspec/changes/archive/` — завершённые изменения
  (`proposal.md`, `design.md`, `tasks.md`, дельты спек).
- `docs/review-prompt.md` — промпт независимого ревьюера; `docs/reviews/` — отчёты ревью с решениями.
- `docs/retro/` — заметка ретроспективы и внедрённое улучшение процесса.
